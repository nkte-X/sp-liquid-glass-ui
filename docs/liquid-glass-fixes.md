# Liquid Glass: аудит и требуемые исправления

Сверка темы (`themes/src/ios-layer.css`) и плагина (`plugin/`) с гайдами Apple:

- [Liquid Glass — Technology Overview](https://developer.apple.com/documentation/technologyoverviews/liquid-glass)
- [Adopting Liquid Glass](https://developer.apple.com/documentation/technologyoverviews/adopting-liquid-glass)
- [Bitrig: Liquid Glass Best Practices](https://bitrig.com/blog/liquid-glass-best-practices)

Версия темы на момент аудита: `--lgx-theme-version: '0.7.3'`.

## 0. Принципы, по которым проверяем

| # | Принцип (Apple / HIG) | Как переводим в CSS-тему |
|---|---|---|
| P1 | Стекло — функциональный слой навигации и контролов над контентом | `backdrop-filter`, блик и glass-тени только у tab bar, шапки, сайдбара, панели-инспектора, кнопки «добавить», compose-карточки, модальных окон |
| P2 | Не класть стекло на стекло | Внутри стеклянной поверхности — плоские заливки (`--lgx-fill*`, `--lgx-glass-lens`), без своего блика, тени и blur |
| P3 | Использовать стекло экономно | Не больше ~5 одновременных слоёв blur на iPhone (уже в спеке §2) |
| P4 | Цвет — только для важного действия или состояния | Tint: главное действие экрана, иконка выбранной навигации, focus ring |
| P5 | Свой цвет — в вариантах light / dark / increased contrast | Акцент хранится парой и имеет high-contrast-вариант |
| P6 | Концентричность | Внутренний радиус = внешний радиус − отступ (аналог `ConcentricRectangle`) |
| P7 | Scroll edge effect под барами, у которых контент прокручивается снизу | Маска сверху под шапкой и снизу под плавающим tab bar |
| P8 | Reduce Transparency, Increase Contrast, Reduce Motion | Каждая полупрозрачная поверхность имеет сплошной вариант; каждая стеклянная — обводку при `prefers-contrast: more` |

Приоритеты: **P0** — баг (ломает читаемость или доступность), **P1** — прямое нарушение гайдов, **P2** — доработка.

## 1. [P0] Reduce Transparency не действует на chrome

### Проблема
Upstream при `prefers-reduced-transparency: reduce` снимает весь blur (`base-liquid-glass.css:1296-1302`, `* { backdrop-filter: none !important }`). Наш слой не переопределяет большинство своих полупрозрачных токенов, поэтому поверхности остаются полупрозрачными **без размытия** — читаются хуже, чем без настройки.

| Поверхность | Где | Почему не работает |
|---|---|---|
| Tab bar | `ios-layer.css:808-811` | `--lgx-glass-bg: var(--lgx-chrome-bg)` объявлен на самом `.mobile-bottom-nav` и перекрывает переопределение на `body` из `:989-999`. Остаётся `rgba(255,255,255,.42)` |
| Сайдбар | `ios-layer.css:606-614` | `background: var(--lgx-chrome-bg) !important` перекрывает сплошной `--sidenav-bg` upstream; `--lgx-chrome-bg` не переопределён |
| Правая панель | `ios-layer.css:851-856` | то же, `--lgx-chrome-bg` |
| Строки панели деталей | `ios-layer.css:863-887` | `--lgx-row-bg`, `--lgx-row-bg-hover` не переопределены |
| Диалоги | `ios-layer.css:905-910` | `--lgx-dialog-bg` не переопределён (0.84 — терпимо, но не сплошной) |
| Меню, select, autocomplete | `ios-layer.css:912-916` | `--lgx-menu-bg` (0.72) не переопределён |
| Диалоги в iframe плагинов | `plugin-iframes.ts:18-35` | берёт `--lgx-dialog-bg` из хоста, `::backdrop` с blur |
| Экран настроек плагина | `plugin/src/app/App.css` | ни одного `@media (prefers-*)` |

### Исправление
1. Ввести отдельный токен для tab bar и не перекрывать глобальный на элементе:
   ```css
   body { --lgx-tabbar-bg: var(--lgx-chrome-bg); }
   body.hasMobileBottomNav .mobile-bottom-nav { background: var(--lgx-tabbar-bg) !important; }
   ```
   Удалить `--lgx-glass-bg: var(--lgx-chrome-bg)` из `:809`. Пресеты Clear / Regular / Tinted (`style.ts:11-14`) переключают `--lgx-tabbar-bg` тоже.
2. Один блок в конце `ios-layer.css`, переопределяющий **все** фоновые токены слоя:
   ```css
   @media (prefers-reduced-transparency: reduce) {
     body {
       --lgx-glass-bg: #f9f9f9;
       --lgx-chrome-bg: #f5f7fa;
       --lgx-tabbar-bg: #f9f9f9;
       --lgx-compose-bg: #ffffff;
       --lgx-dialog-bg: #ffffff;
       --lgx-menu-bg: #ffffff;
       --lgx-row-bg: #ffffff;
       --lgx-row-bg-hover: #f0f3f7;
     }
     body.isDarkTheme {
       --lgx-glass-bg: #2c2c2e;
       --lgx-chrome-bg: #181b23;
       --lgx-tabbar-bg: #2c2c2e;
       --lgx-compose-bg: #2c2c2e;
       --lgx-dialog-bg: #2c2c2e;
       --lgx-menu-bg: #2c2c2e;
       --lgx-row-bg: #1c1c1e;
       --lgx-row-bg-hover: #2c2c2e;
     }
   }
   ```
   Существующие разрозненные блоки (`:296-303`, `:989-999`) слить в этот.
3. В этом же блоке снять `::after`-кольцо tab bar (`:636-653`) и инсет-блики сайдбара — без прозрачности они выглядят как рамка.
4. `App.css`: добавить `@media (prefers-reduced-transparency: reduce)` — сплошные `.group`, `.segmented`, `.actions button`, без `backdrop-filter`.
5. `plugin-iframes.ts`: при `prefersReducedTransparency()` отдавать сплошной `dialog` и `::backdrop` без blur.
6. `env.ts:48-51`: `prefersReducedTransparency()` / `prefersReducedMotion()` вычисляются разово. Подписаться на `change` у `MediaQueryList` (через `Disposer`) и перезапускать зависящие функции — пользователь может переключить настройку при открытом приложении.

### Критерий приёмки
С включённым Reduce Transparency на iOS и macOS ни одна поверхность chrome, overlay или контента не показывает обои или контент сквозь себя. Диагностика плагина (`diagnostics.ts`) показывает актуальное значение после переключения без перезапуска.

## 2. [P1] Стекло в контенте

### 2.1. Карточки задач Glass / Frosted
**Где:** `style.ts:76-124`, настройка в `settings.ts`, `protocol.ts`, `App.tsx`.

**Проблема:** строки списка — главный контент приложения. Glass делает их полупрозрачными с бликом и двойной тенью, Frosted добавляет live blur на каждую карточку. Это ровно тот случай, от которого предостерегают оба гайда (стекло на карточках и списках), плюс нагрузка на длинных списках.

**Исправление:**
- Удалить режим **Frosted** целиком (CSS, значение в протоколе, пункт в UI).
- Режим **Glass** переименовать в **Translucent** и оставить мягким: только полупрозрачный фон (`--task-c-bg` около 0.7 / 0.6 для тёмной), **без** инсет-блика, без двойной тени, без blur.
- По умолчанию — **Solid** (как сейчас).
- Миграция: сохранённое значение `frosted` читать как `translucent` (по аналогии с проигнорированным ключом `refraction`, README «Удалено»).

### 2.2. Строки панели деталей задачи
**Где:** `ios-layer.css:863-899`.

**Проблема:** каждая строка — отдельная «стеклянная карточка» с бликом и тенью внутри стеклянной правой панели. Стекло на стекле (P2) и стекло в контенте (P1).

**Исправление:**
- Строки — iOS inset-grouped ячейки: фон `--lgx-grouped-cell` (в тёмной теме `#1c1c1e`) или `--lgx-fill-2`, без `box-shadow`-блика.
- Соседние строки собрать в один блок как у подзадач (`:469-506`): без зазоров, скруглены только внешние углы блока, между строками волосок `--lgx-separator`.
- Hover — смена заливки, без тени.
- Focus — `0 0 0 2px` цвета tint, без инсет-блика.

### 2.3. Группы на экране настроек плагина
**Где:** `App.css:497-514` (`.group`), `:557-575` (`.actions button`).

**Проблема:** группы формы — на blur 30px с бликом, внутри — стеклянные кнопки на blur 20px. В спеке это записано как решение (`design-spec.md:83`), но у Apple сгруппированные формы — сплошные ячейки, а стекло получают только контролы.

**Исправление:**
- `.group`: сплошной фон (`#fff` / `#1c1c1e`, при обоях допустима непрозрачность 0.9 без blur), радиус по системе из §4, без блика.
- `.actions button`: обычная iOS-кнопка (заливка `--lgx-fill` или tint для главной), без `backdrop-filter`.
- Сегментный переключатель — без изменений по материалу, но выбранный сегмент без внешней тени (см. §5.1).
- Обновить строку §4 спеки «Экран настроек плагина».

### Критерий приёмки
`grep -n "backdrop-filter" themes/src/ios-layer.css plugin/src` находит только поверхности из списка P1 (tab bar, кнопка «добавить», группы шапки, сайдбар, правая панель, compose-карточка, диалоги, меню, sheet) и превью-карточки редактора обоев.

## 3. [P1] Акцентный цвет

### 3.1. Один hex на обе темы
**Где:** `accent.ts:47-68`.

**Проблема:** палитра строится из одного цвета для светлой и тёмной темы. Системные цвета iOS — пары (`#007AFF` / `#0A84FF`, `#34C759` / `#30D158` …), и Apple требует для своего цвета вариант для тёмной темы и для повышенного контраста.

**Исправление:**
- Формат настройки: `accent: { light: string; dark: string } | systemColorId`. Для системных цветов — встроенная таблица пар (те же значения, что в токенах `--lgx-*`, `ios-layer.css:31-36` и `:96-101`).
- Для своего цвета тёмный вариант выводить автоматически (поднять светлоту в OKLCH примерно на 6–8 %), с возможностью задать вручную в `ColorPicker.tsx`.
- `accent.ts` пишет обе палитры и переключает их по `body.isDarkTheme` (MutationObserver уже есть в `plugin-iframes.ts` — вынести в общий хелпер).
- Добавить high-contrast варианты для `prefers-contrast: more` (для системных — accessible-варианты Apple, например blue `#0040DD` / `#409CFF`; для своего — затемнение / осветление до контраста 4.5:1 к фону).
- Миграция: старое строковое значение = `{ light: hex, dark: derived(hex) }`.

### 3.2. Tint на всём
**Где:** принцип «один цвет на всё» (`design-spec.md:79`, README строка «Акцентный цвет»), правила `ios-layer.css:207, 349, 376, 586, 610, 626, 678, 844-848`.

**Проблема:** tint одновременно на кнопке «добавить», кнопке отправки, Play, чипах со значением, подсветке синтаксиса, иконке выбранного таба, иконке **и** фоне выбранного пункта сайдбара. Гайд: «если выделено всё, не выделено ничего».

**Исправление — где tint остаётся:**
- главное действие экрана: `.add-task-button`, `.add-task-submit-btn`, Play;
- иконка выбранного таба и выбранного пункта сайдбара;
- focus ring;
- подсветка короткого синтаксиса (это контент, допустимо, но приглушить: 20 % вместо 28 %, без обводки).

**Где tint убрать:**
- фон выбранного пункта сайдбара (`:610`, `:626`) → нейтральная заливка `--lgx-glass-lens`;
- чипы со значением в compose (`:375-377`) → `--lgx-fill`, цвет текста — `--lgx-label`, tint только у иконки.
- Цветная тень кнопок prominent (`:62-66`, `:120-124`, `color-mix(tint 35%)`) → нейтральная тень, как у остальных glass-кнопок.

Обновить спеку: заменить «один цвет на всё» на «tint только у главного действия и выбранного состояния».

### Критерий приёмки
На экране Today с выбранным акцентом цвет tint виден не более чем в 3 местах вне контента (кнопка «добавить», выбранный таб / пункт сайдбара, Play). При системном синем в тёмной теме используется `#0A84FF`.

## 4. [P2] Концентричные радиусы

### Проблема
Сейчас радиусы задаются числами независимо друг от друга: sheet 38, alert 34, диалог 26, compose 26, menu 24, snackbar / autocomplete 22, сайдбар 22 (Mac 14), строка задачи 18, строки деталей 16, подзадачи 14, пункты сайдбара 12, поле поиска 14.

Конкретные несоответствия:

| Пара | Сейчас | Концентрично |
|---|---|---|
| Панель сайдбара → пункт | 22 → 12 при отступе пункта ~8 | 22 − 8 = **14** |
| Compose-карточка → кнопка отправки | 26 → круг 44 (r = 22) в отступе 8 | 26 − 8 = **18**, либо оставить круг и уменьшить отступ до **4** |
| Окно macOS Tahoe → панель сайдбара | ? → 14 при отступе 4 | радиус угла окна − 4 (замерить угол окна на устройстве, как замеряли кнопки окна) |
| Диалог → кнопки-капсулы | 34 / 26 → капсулы | капсулы концентричны всегда, но отступ кнопок от края диалога должен давать `радиус диалога − отступ ≥ радиус капсулы / 2` |
| Группа настроек → сегментный переключатель | 22 → ? | 22 − отступ группы |

Противоречие в спеке: §4 указывает радиус диалогов и 26 px (`design-spec.md:88`), и 34 px (`:94`). В CSS: 34 на iOS (`ios-layer.css:534`), 26 на остальных (`:905`).

### Исправление
1. Ввести внешние радиусы как токены и выводить внутренние:
   ```css
   body {
     --lgx-r-window: 26px;    /* уточнить замером на Tahoe */
     --lgx-r-sheet: 38px;
     --lgx-r-alert: 34px;
     --lgx-r-panel: 22px;
     --lgx-r-card: 26px;      /* compose */
     --lgx-r-menu: 24px;
     --lgx-r-row: 18px;
     --lgx-pad-panel: 8px;
     --lgx-pad-card: 8px;
   }
   magic-side-nav .nav-link { border-radius: calc(var(--lgx-r-panel) - var(--lgx-pad-panel)) !important; }
   body.isMac.isElectron magic-side-nav .nav-sidenav {
     border-radius: calc(var(--lgx-r-window) - var(--lgx-mac-panel-inset)) !important;
   }
   ```
2. Заменить все числовые `border-radius` в `ios-layer.css` и `App.css` на токены или `calc()` от них. Исключения — капсулы (`999px`) и круги (`50%`).
3. Решить единый радиус диалога (рекомендация: 34 на всех touch-платформах, 26 на desktop как у macOS-алертов) и исправить спеку.
4. В спеке §3 заменить строку «Геометрия» таблицей «контейнер → отступ → вложенный радиус».

### Критерий приёмки
В `ios-layer.css` нет числовых `border-radius`, кроме `0`, `999px`, `50%` и самих токенов. Визуально углы вложенных элементов параллельны углам контейнера (проверка в `preview/ios-preview.html` и на Mac).

## 5. [P2] Стекло на стекле внутри chrome

### 5.1. Выбранный таб и выбранный пункт сайдбара как вторая линза
**Где:** `ios-layer.css:813-824` (таб), `:662-674` (сайдбар), `App.css` `.segmented button.on`.

**Проблема:** у выбранного элемента свой инсет-блик и внешняя тень — он читается как отдельное стекло поверх стеклянной капсулы / панели. В iOS 26 выбранный таб в покое — плоская подложка, а линзой становится только во время взаимодействия.

**Исправление:** оставить только заливку `--lgx-glass-lens` (сайдбар — см. §3.2). Убрать внешнюю тень; инсет-блик — не больше `inset 0 0.5px 0 rgba(255,255,255,.4)` или убрать. В `App.css` выбранному сегменту убрать `0 3px 10px` / `0 4px 14px` тени.

### 5.2. Скрим с размытием в диалогах плагинов
**Где:** `plugin-iframes.ts:31-35`.

**Проблема:** `::backdrop` с blur 6px под диалогом с blur 40px — два слоя размытия. В iOS скрим только затемняет.

**Исправление:** `::backdrop { background: rgba(0,0,0, dark ? .45 : .22) }` без `backdrop-filter`.

### 5.3. Группы шапки и открываемые ими меню
Проверить: меню, открытое из стеклянной группы шапки, не должно лежать на этой группе (только рядом). Сейчас ок по коду; зафиксировать в чек-листе §9.

## 6. [P2] Bottom sheet

**Где:** `ios-layer.css:512-528`.

**Проблема:** у sheet только радиус и граббер. В iOS 26 половинный sheet отступает от краёв экрана (под ним видно контент), а развёрнутый на всю высоту становится плотнее.

**Исправление:**
- Половинное состояние: `margin-inline: 8px` (плюс safe area), нижний отступ 8 px, все четыре угла — `--lgx-r-sheet`. Внутренний контент — отступ не меньше `--lgx-r-sheet − 8` от углов, чтобы не налезать на скругление.
- Полная высота: фон из Tier B до непрозрачности ≈ 0.92, отступы 0, нижние углы 0. Если состояние в DOM не различимо классом — определять по высоте контейнера в плагине (`ResizeObserver`) и ставить `lgx-sheet-full`.
- Проверить, что видимый между sheet и краем контент выглядит как ожидается (Apple: «check the content around the edges of sheets»).

## 7. [P2] Scroll edge effect снизу

**Где:** `style.ts:180-218`, `scroll-edge.ts`.

**Проблема:** мягкий край есть только сверху. Контент, уходящий под плавающий tab bar, ничем не приглушается, и на светлом контенте капсула теряется.

**Исправление:** для прокручиваемых областей при `hasMobileBottomNav` добавить нижнюю маску высотой примерно `--lgx-tabbar-h / 2`, затухающую к `--lgx-tabbar-bottom`. Показывать, только когда снизу есть невидимый контент (`scrollTop + clientHeight < scrollHeight`). Off / Soft / Hard действуют на оба края. Blur под маской не использовать (см. замечание в `style.ts:178`).

## 8. [P2] Increase Contrast

**Где:** `ios-layer.css:1001-1008`.

**Проблема:** обводка есть только у tab bar, кнопки «добавить» и групп шапки.

**Исправление:** при `prefers-contrast: more`:
- обводка `1px solid var(--lgx-label-2)` также у сайдбара, правой панели, compose-карточки, диалогов, меню, sheet, групп и сегментного переключателя в `App.css`;
- `--lgx-label-2` поднять до 0.8, `--lgx-separator` — до непрозрачного;
- стеклянные фоны уплотнить (+0.25 к непрозрачности);
- акцент — high-contrast вариант (§3.1).

## Статус (тема 0.8.0, плагин 0.7.0)

Все разделы 1–9 выполнены; открытые решения приняты по рекомендациям: Translucent вместо Glass, Frosted удалён; tint только у главного действия и выбранного состояния; диалоги 34 на touch и 26 на desktop.

Отступление от §3.1: формат настройки — не объект в `accent`, а два ключа `accent` (светлый hex или системный цвет) и `accentDark` ('' = вывести). Настройки синхронизируются между устройствами, и старая сборка плагина на другом устройстве отбросила бы объект как невалидный и сбросила бы акцент. Со строкой в `accent` она продолжает работать. Миграция не нужна: старое значение уже валидно, тёмный вариант выводится.

Проверено: `npm run smoke` 88/88 (WebKit, превью), валидатор темы, геометрия шапки и сайдбара на веб-приложении с эмуляцией Mac. Не проверено на устройстве: радиус угла окна Tahoe (`--lgx-r-window: 26px` — оценка), sheet на iPhone, Reduce Transparency в живом режиме (headless-браузеры его не эмулируют; правила проверены по собранному CSS).
